# Entrada y salida

**Estilo:** directo, sin funciones asíncronas · **Concurrencia:** estructurada · **Buffers:** por movimiento

La entrada y salida se escribe igual sin importar cómo espere: el código hace una operación y recibe su resultado. Qué ocurre mientras espera lo decide el motor, un proveedor elegido en el paquete raíz.

## <a id="es-principios"></a>Principios

- <a id="es-principios-1"></a>**Toda E/S es un efecto declarado.** Lo que un programa puede tocar está en sus firmas. `es-principios-1`
- <a id="es-principios-2"></a>**Estilo directo.** No existen funciones asíncronas. Una función que hace E/S se llama como cualquier otra y sirve con cualquier motor. `es-principios-2`
- <a id="es-principios-3"></a>**Concurrencia estructurada.** Toda tarea pertenece a un ámbito y termina antes que él. `es-principios-3`
- <a id="es-principios-4"></a>**Buffers por movimiento.** Una operación toma el buffer y lo devuelve al terminar; nadie puede tocarlo mientras el sistema lo usa. `es-principios-4`
- <a id="es-principios-5"></a>**Fronteras.** Toda E/S cruza una [frontera asíncrona](02-nucleo.md#nuc-fronteras) con su modelo de fallos. `es-principios-5`

## <a id="es-motor"></a>Motores

| Tipo de motor             | Tareas                                              | Espera                                           |
|---------------------------|-----------------------------------------------------|--------------------------------------------------|
| De hilos `es-motor-1`     | Un hilo del sistema por tarea                       | Llamadas bloqueantes                             |
| De eventos `es-motor-2`   | Tareas ligeras repartidas en hilos                  | La cola de finalización o de eventos del destino |
| Simulado `es-motor-3`     | Tareas ligeras en un hilo con planificador sembrado | Reloj, red y almacenamiento simulados            |
| Del programa `es-motor-4` | Las que defina                                      | Interrupciones de hardware, en freestanding      |

## <a id="es-tareas"></a>Tareas, ámbitos y cancelación

- <a id="es-tareas-1"></a>Un ámbito crea tareas y, al cerrarse, espera a todas las que sigan activas. Si sale antes de tiempo, cancela sus tareas y las espera. `es-tareas-1`
- <a id="es-tareas-2"></a>Un ámbito puede tener plazo; al vencer, cancela sus tareas y sus esperas terminan con plazo vencido. `es-tareas-2`
- <a id="es-tareas-3"></a>Puede esperarse la primera de varias operaciones; las demás se cancelan. `es-tareas-3`
- <a id="es-tareas-4"></a>La cancelación es cooperativa: cada espera es un punto de cancelación que devuelve un error; un cálculo largo sin esperas consulta si fue cancelado. `es-tareas-4`

## <a id="es-canales"></a>Canales y contrapresión

<a id="es-canales-1"></a>Los canales tienen capacidad fija; enviar a uno lleno espera, y existe un envío que no espera y devuelve error. No hay colas sin límite: la contrapresión es siempre explícita. `es-canales-1`

## <a id="es-pila"></a>Pila de las tareas

<a id="es-pila-1"></a>Con tareas ligeras, cada una tiene una pila de tamaño fijo que el verificador calcula a partir del grafo de llamadas cuando no hay recursión o su profundidad está acotada por una medida con cota. Si no puede acotarse, la tarea declara su cota y su pila lleva una guarda que aborta la tarea si se desborda; esa comprobación aparece en el diff de significado. `es-pila-1`

## <a id="es-simulacion"></a>Simulación determinista

<a id="es-simulacion-1"></a>El motor simulado ejecuta todas las tareas en un hilo con un planificador sembrado, un reloj virtual y fronteras simuladas. Con la misma semilla, la ejecución se repite exactamente. Puede inyectar los fallos que cada frontera declara, para comprobar que los contratos de error se cumplen. `es-simulacion-1`
